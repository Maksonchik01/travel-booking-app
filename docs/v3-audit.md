# SkyPack V3 — початковий технічний аудит

Дата: 2026-11-11. Лише читання коду й конфігурації: жодних змін, платних запитів чи дій з продакшн-даними.

## Що вже працює добре (лишаємо)

- **Запити до джерел:** `ProviderGate` (ліміт одночасних, повтор лише 502–504/обриву з jitter, 429/4xx — без повтору),
  загальний тайм-аут джерела, graceful degradation (`coverage`, статуси джерел).
- **Кеш і дедуплікація:** `CachedFlightProvider` / `CachedStayProvider` (Redis, один виклик на однакові запити, замок
  між процесами), ключ `search_cache_payload`, свіжість ціни (`freshness`).
- **Ліміти на один пошук:** SerpApi ≤ 4 запити, scrape.do ≤ 2; алерти ніколи не ходять у платні джерела (валідація `Settings`).
- **Акаунти:** scrypt, httpOnly + SameSite=Lax + Secure cookie, у БД лише SHA-256 токена, усі операції з поїздками, обраним,
  чатами, пошуками й алертами фільтруються за `user_id`. Токени — `secrets.token_urlsafe` (публічна поїздка — 144 біти).
- **База:** RLS на кожній таблиці (`test_row_level_security`), каскади від `users`, CHECK-переліки, CI — міграції
  upgrade → downgrade → upgrade.
- **Перенаправлення:** `/out` — лише дозволені префікси після нормалізації URL.
- **Помилки й PII:** Sentry без PII, `redact_secrets` у логах, текст запитів користувача не логуємо.
- **CI:** ruff, mypy strict, pytest з Postgres/Redis, eslint, tsc, vitest, build, Playwright.

## Знахідки

### Критичні — витрати

| # | Проблема | Наслідок |
|---|---|---|
| C1 | Немає спільного бюджету платних API. Ліміт — лише 40 пошуків/год на IP. | Один пошук рейсів — до 5 запитів SerpApi (4 + перевірка продавців) і до 20 кредитів scrape.do. Одна людина за годину може витратити всю місячну квоту SerpApi (250) і більшу частину scrape.do (1000). IP легко змінити. |
| C2 | Немає обліку використання й вартості SerpApi та scrape.do. | Є лише лічильники охоплення й запит квоти SerpApi в `/ops/summary`. Витрати не видно, собівартість пошуку невідома. |
| C3 | Дорогі операції в одному «кошику» лімітів із дешевими. | «Знайти дешевший варіант» — два повні плани поїздки (≈ 10 SerpApi + до 100 кредитів scrape.do). Explore «+ житло», пошук поїздки, тарифи й деталі житла рахуються так само, як автодоповнення. |

### Високі

| # | Проблема |
|---|---|
| H1 | Без rate limit: `GET /flights/calendar`, `/flights/matrix` (запити до Travelpayouts), `/flights/history`, `/stays/history` (запити до БД), `/places`, публічна поїздка. |
| H2 | Ліміт лише за IP: акаунт не враховується, немає ліміту одночасних пошуків на клієнта. |
| H3 | ШІ: є лише ліміт викликів на один запит. Добового чи місячного ліміту витрат немає: вартість видно в `/ops/summary`, але її ніщо не зупиняє. |
| H4 | Немає технічних сповіщень власнику: про бюджет, недоступність джерел, різкий ріст помилок. Sentry ловить лише винятки. |

### Середні

| # | Проблема |
|---|---|
| M1 | Веб без заголовків безпеки: CSP / `frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` (є лише на `/out` і аватарі). |
| M2 | API у продакшні віддає `/docs`, `/redoc`, `/openapi.json` (FastAPI за замовчуванням). |
| M3 | Немає ідентифікатора запиту в логах API (є лише в `llm_usage`). |
| M4 | Продуктивність (LCP/INP/CLS, час пошуку) не вимірювалась. Навантажувальних тестів немає. |
| M5 | Процедура відкату й відновлення з резервних копій Supabase не задокументована. Free-план Supabase: доступність резервних копій треба перевірити в дашборді. |

### Низькі / прийняті

- Префікс `https://www.google.com/aclk?` — відкрите перенаправлення Google для рекламних посилань продавців. Прийнято: це офіційні посилання з видачі.
- Render free: перший запит після сну — до хвилини (відомо, ADR 0012).

## План етапів

1. ✅ Аудит (цей документ).
2. ✅ Бюджет платних API та облік витрат: C1, C2 ([ADR 0055](adr/0055-api-budget-and-spend.md)). Централізований лічильник у Redis (атомарний, з урахуванням одночасних запитів), добові й місячні ліміти, резерв для обов'язкових операцій, вимкнення необов'язкових дорогих операцій, собівартість успішного пошуку.
3. ✅ Ліміти зловживань: C3, H1, H2 ([ADR 0056](adr/0056-abuse-limits-and-ai-spend.md)). Окремі кошики для дорогих операцій, акаунт + IP, ліміт одночасних пошуків. Ліміти витрат ШІ: H3.
4. ✅ Безпека: M1, M2, M3 ([ADR 0057](adr/0057-security-hardening.md)), повторна перевірка RLS / авторизації / XSS / SSRF.
5. Провайдери й кеш: TTL, ключі, поетапний пошук, нормалізація, дублікати.
6. Точність цін і результатів: перельоти, житло, поїздки, арифметика.
7. Збої й тести: сценарії 429/5xx/тайм-аут/бюджет, нестандартні кейси.
8. Навантажувальний тест на mock-провайдерах: P95, частка помилок, зовнішні виклики.
9. Продуктивність вебу й пошуку: M4.
10. Моніторинг і сповіщення власнику, компактна адмін-сторінка: H4.
11. Деплой і відновлення (M5) та фінальний аудит і звіт.

## Знайдено під час робіт

- **Етап 3:** нестабільний тест `test_alerts::test_check_all_reuses_searches_respects_budget_and_skips_fresh`
  (≈ 1 з 12 прогонів): перевірка алертів сортувала лише за `last_checked_at`, і серед нових підписок порядок був
  випадковим. Виправлено детермінованим порядком (`created_at`, `id`) — старіші підписки першими.
- **Етап 4:** відкрите перенаправлення після входу (`next=/\evil.example`) — виправлено (`safeLocalPath`).
