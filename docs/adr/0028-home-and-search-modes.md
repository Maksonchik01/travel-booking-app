# ADR 0028: Головна сторінка, режими пошуку й бренд SkyPack

- Статус: прийнято (2026-11-09). Модуль 12.

## Контекст
ТЗ 12: головна має швидко пояснити, навіщо сервіс (авіаквитки, порівняння, житло, поїздка,
економія часу), без рекламного перевантаження; одна зрозуміла перемичка «Авіаквитки / Житло /
Поїздка / ШІ-пошук», що зберігає сумісні параметри; компактний блок трьох можливостей без
необґрунтованих тверджень. Власник обрав назву SkyPack.

## Рішення
- **Бренд** у всьому, що бачить людина: шапка, заголовки, листи, бот, юридичні тексти, назва API.
  Внутрішні імена (пакети `tickets_*`, ключі `tickets.*` у сховищі браузера, cookie сесії)
  лишаються — їх зміна зламала б збережені дані без користі.
- **Hero**: заголовок про подорож в одному місці, підзаголовок і рядок із п'яти коротких
  можливостей з іконками; стриманий стиль без нових кольорів.
- **Режими** (`components/search-modes.tsx`, `lib/search-modes.ts`): над карткою пошуку на `/`,
  `/stays`, `/trip`. Перехід переносить спільне — куди (для житла — місто), дати (заїзд/виїзд),
  дорослих і дітей — з ПОТОЧНОЇ форми, навіть не надісланої (`form[data-search-form]`); без JS —
  посилання з параметрів URL. Неповне (напр. житло без міста вильоту для перельоту) підставляється
  у форму як чернетка, пошук не запускається. «ШІ-пошук» перемикає картку на помічника на тій
  самій сторінці (події на спільному контейнері — без впливу на приховані сторінки).
  Старі вкладки «Пошук / ШІ-помічник» прибрано — їхню роль виконує перемикач.
- **Три можливості**: пошук доступних пропозицій (з віком ціни), порівняння варіантів, подорож
  під бюджет — лише те, що сервіс справді робить, без «гарантовано найнижчої ціни».
