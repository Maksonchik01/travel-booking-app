# ADR 0023: Кабінет — розділи, обране за категоріями, статуси поїздок

- Статус: прийнято (2026-11-08). Модуль 10a; розширює ADR 0011, 0020, 0021.

## Контекст
ТЗ модуля 10 (10.1–10.4): кабінет як центр керування — розділи «Огляд», «Обране», «Мої
поїздки», «Історія пошуку», «Сповіщення», «Налаштування», «Безпека»; головна сторінка зі
швидкими діями; обране в трьох категоріях (квитки, житло, готові поїздки) з параметрами
пропозиції й часом отримання ціни; статуси поїздок без «заброньовано».

## Рішення
- **Розділи — окремі сторінки** `/account`, `/account/{favorites,trips,history,alerts,settings,
  security}` з однаковою оболонкою (`components/account-shell.tsx`: бічна навігація з активним
  розділом, повідомлення `done=`/`error=`, `requireAccount` — без входу на `/login?next=`).
  Наявні форми перенесено без змін; дії кабінету ревалідують увесь `/account` (layout).
  Публічні `/favorites` і `/trips` лишаються для гостей — ті самі компоненти.
- **Огляд**: привітання, швидкі дії (новий пошук, спланувати поїздку, мої поїздки, створити
  сповіщення), збережені поїздки, активні сповіщення, останні пошуки, обрані маршрути (обрані
  квитки + збережені пошуки перельотів).
- **Обране** (`favorites.kind`: stay / flight / trip; дані — JSON знімка, перевірений моделлю
  категорії): квиток — `source:id`, маршрут, час, склад, ціна з `price_status` і `price_at`,
  рядок пошуку; поїздка — запит з вибором рейсу й житла + `TripSnapshot`. Дії: повторити пошук,
  до планувальника, прибрати. Записи браузера модуля 7 (без `kind`) читаються як житло.
- **Статуси поїздок** `saved_trips.status`: draft (за замовчуванням) / planned / archived;
  змінює лише `PATCH /account/trips/{id}` — «Зберегти зміни» з планувальника статус не скидає.
  Минулі дати — підказка перенести в архів. «Заброньованої» немає: бронювання SkyPack не бачить.
- Історія пошуку поїздок пише сам пошук без вибору рейсу й житла.
