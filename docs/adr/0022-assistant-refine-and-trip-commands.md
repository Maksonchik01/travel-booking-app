# ADR 0022: Помічник — уточнення пошуку й команди готової поїздки

- Статус: прийнято (2026-11-08). Розширює ADR 0007.

## Контекст
ТЗ модуля 9 (9.1–9.3): діалоговий пошук з уточненням лише відсутніх обов'язкових
параметрів, контекст розмови («лише прямі» → «після 18:00» → «бюджет 600» — кожне змінює
тільки своє), команди готової поїздки («дешевший готель», «не змінюй авіаквитки», «швидший
переліт», «бюджет +100», «поверни», «порівняй», «збережи»), що змінюють реальний стан.

## Рішення
- **Уточнення — патчем, не переписуванням**: `refine_flights` / `refine_stays`
  (`ai/refine.py`) — модель передає лише зміни, код накладає їх на поточний пошук
  (`current_search` з URL або останній пошук репліки) і валідує. Відносні зміни
  (`max_price_change`, `budget_change`) рахує код; немає від чого — помилка, модель питає.
  Відповідь інструмента містить `active_filters` — модель називає умови, що діють.
- **Нова поїздка**: `plan_trip` приймає період (`departure_until`), тривалість (ночі),
  прямі, багаж і побажання до житла (рейтинг, відстань, скасування, сніданок, тип).
- **Готова поїздка**: веб передає `current_trip` (запит з URL планувальника, з `flight`/`stay`)
  і `previous_trip` (попередній крок зі стеку вкладки). `change_trip` — умови через
  `refine_trip`, заміна рейсу/житла — вибір КОДОМ серед варіантів планувальника
  (`pick_flight`, `pick_stay`; тип житла той самий), «keep» закріплює компонент. Результат —
  новий запит з вибором (`trip_search`), UI переходить на нього; до/після й різницю рахує код.
  `undo_trip` → `trip_action: "undo"` (UI робить крок назад стеком вкладки);
  `compare_trips` → `compare` (знімки для панелі порівняння); `save_trip` → `save_trip`
  (UI зберігає як кнопка «Зберегти поїздку»: акаунт або браузер).
- **Не вигадувати**: промпти вимагають питати лише відсутнє обов'язкове, не передавати
  кількість людей, якщо її не названо (і казати про це), і казати, коли взято
  `home_airport`. Числа у відповіді, як і раніше, звіряються з результатами інструментів.
- Mock-LLM розпізнає кілька ключових слів (сценарій для e2e, не розуміння мови).

## Наслідки
- Кожна команда поїздки — 1 пошук перельотів у ліміті репліки (`MAX_SEARCHES_PER_TURN`);
  повторні плани того самого запиту — з кешу джерел.
- Картки результатів у чаті й перенесення ШІ ↔ планувальник — модуль 9b; історія чатів — 9c.

## Модуль 9b: картки в чаті й перенесення ШІ ↔ планувальник
- **Картки** (`ai/cards.py`, `ChatReply.cards`) будує код з результатів інструментів репліки —
  ті самі варіанти, що бачить модель: квитки (маршрут, авіакомпанії, час, тривалість, пересадки,
  ціна за всіх), житло (фото лише https від джерела, назва, рейтинг, район/відстань, ціна),
  поїздка (переліт, житло, сума відомого й невідомі складові). Кожна несе статус ціни: жива чи
  кешована з часом знаходження — UI позначає кешовану старшу за добу (9.6).
- **ШІ → планувальник**: картка поїздки містить `TripQuery` з `flight`/`stay` — «Відкрити в
  планувальнику» відкриває саме цю комбінацію; квиток туди-назад — «Спланувати поїздку з цим
  рейсом» (`flight=`), житло — «Додати до поїздки» (`stay=`).
- **Планувальник → ШІ**: «Оптимізувати з ШІ» в «Вашій поїздці» — подія `ai:open`
  (`lib/ai-events.ts`): вкладка помічника, нова розмова «Уся поїздка» з чернеткою. Поїздку чат
  бере з URL сторінки (`current_trip`), тож усі параметри — без втрат. Попередні сторінки Next
  тримає змонтованими (прихованими), тому обробники звіряють `usePathname()` з адресою вікна.
- Картки зберігаються в репліках історії браузера (`StoredTurn.cards`) з готовими посиланнями.

## Модуль 9c: історія чатів і синхронізація за згодою
- Історія — як і раніше в браузері (`lib/chat-history.ts`): список, продовження, новий чат,
  видалення; додано перейменування.
- **Синхронізація між пристроями — лише за згодою** (`users.chat_sync`, за замовчуванням
  вимкнено, перемикач в «Історії» чату). Увімкнули — розмови цього браузера вивантажуються в
  `chat_conversations` (RLS, до 30, ключ — id розмови з браузера), далі кожна зміна; на іншому
  пристрої — злиття «новіше перемагає» (`mergeStores`), сервер теж не перезаписує новішу
  копію старішою. Вимкнули — відкликання згоди: розмови з акаунта видаляються (у браузері
  лишаються). Видалення акаунта видаляє їх теж.
- Синхронізовані дані перевіряє сервер (`domain/chats.py`): посилання — лише шляхи нашого
  сайту, фото — лише https, обмежені розміри. Текст розмов у логи не пишемо, як і раніше.
