# ADR 0004: невідомі деталі пересадок у кешованих джерелах

- Статус: прийнято (етап 1)

## Контекст
Travelpayouts Data API (`/aviasales/v3/prices_for_dates`) повертає лише кількість
пересадок (`transfers`, `return_transfers`) і тривалість (`duration_to`, `duration_back`).
Аеропортів пересадок, їх тривалості, нічних і самостійних пересадок у даних немає.
Скоринг (етап 2) штрафує саме за ці ризики.

## Рішення
- `Leg.layovers = None` означає «деталі невідомі», а `[]` — «пересадок немає».
- `Offer.details_level`: `full` (є сегменти й пересадки) або `summary`.
- Скоринг і UI показують невідомі деталі як окремий ризик («деталі пересадок
  невідомі»), а не вважають їх відсутніми. Це рішення власника продукту.

## Наслідки
- Повні деталі можливі лише з джерела реального часу (Aviasales Flight Search API,
  потребує схвалення Travelpayouts) — окремий адаптер за тим самим інтерфейсом.

## Доповнення (реальні дані, 2026-11-02)
- `duration_to`/`duration_back` — час у повітрі; повний час у дорозі — `duration`.
  Наземний час пересадок = `duration − duration_to − duration_back`; його приписуємо
  напрямку, лише якщо пересадки є тільки в ньому. Інакше по напрямках тривалість
  невідома, а загальна береться з `duration` (`Offer.reported_total_duration_min`).
- Час прильоту API не дає, а без поясу аеропорту прильоту його не порахувати — в UI
  показуємо лише аеропорт прильоту й тривалість.
