# ADR 0035 — Продуктивність фронтенду

Статус: прийнято (модуль 17b, 17.5).

## Контекст

Аудит продакшн-збірки (`next build`, Turbopack). Розміри Next 16 у звіті не показує, тому їх рахуємо з маніфестів збірки (`server/app/[locale]/page/build-manifest.json` → `rootMainFiles`).

Уже було зроблено:
- **Перехід між сторінками:** статичні оболонки сторінок (PPR, `cacheComponents`) і `partialPrefetching`.
- **Картинки й шрифти:** `next/image` для логотипів і фото профілю, `loading="lazy"` для фото житла, `next/font`.
- **Мережа:** тайм-аути запитів із браузера (`client-fetch.ts`), пауза й скасування в автопідказках, кеш браузера для `/api/places`, ліниве `import("maplibre-gl")`.
- **Списки:** «Показати ще» без нових запитів.

Знайдено:
1. **Sentry SDK у спільному бандлі:** ≈ 58 КБ gzip на кожній сторінці, навіть без DSN.
2. **Усі переклади в браузері:** `NextIntlClientProvider` без `messages` передавав увесь словник (110 КБ), зокрема юридичні тексти (17 КБ), які читає лише сервер.
3. **CSS карти на сторінці житла:** `stay-map.tsx` імпортував CSS MapLibre статично, тож 71 КБ блокувального CSS вантажилися і в режимі «Список».
4. **Подвійні запити в межах рендера:** `fetchAIStatus` і `fetchAlertChannels` викликаються кількома частинами сторінки. `fetch` із `signal` Next сам не об'єднує, тож виходило 2–3 однакові запити до API.
5. **Довгі видачі:** до 80 карток в одному списку, браузер верстає їх усі.

## Рішення

1. **Ліниве завантаження Sentry** (`lib/sentry-client.ts`): SDK вантажиться окремим чанком, коли браузер вільний (`requestIdleCallback`), а без DSN не вантажиться зовсім. Помилки до завантаження ловлять ранні обробники й передають у SDK. `global-error` звітує через `reportError`. Трасування не було й немає, тож `onRouterTransitionStart` прибрано.
2. **Лише клієнтські переклади** (`lib/client-messages.ts`): у `NextIntlClientProvider` передаються тільки розділи, які читає клієнтський код. Тест `client-messages.test.ts` обходить імпорти від кожного `"use client"` і падає, якщо компонент читає розділ поза списком.
3. **Карта окремим чанком** (`stay-map-lazy.tsx`, `next/dynamic`, `ssr: false`): MapLibre і його CSS вантажаться лише в режимі «Карта». Поки чанк іде, показується заглушка того самого розміру, без зсуву сторінки.
4. **`cache()` (React)** для `fetchAIStatus` і `fetchAlertChannels`: один запит на рендер.
5. **`content-visibility: auto`** для карток видачі (`show-more.tsx`): картки за екраном не верстаються й не малюються. У тестах доступності ця оптимізація вимикається, бо axe не бачить кольорів неотрисованого.

## Результат (продакшн-збірка, gzip)

| | До | Після |
|---|---|---|
| Спільний JS на кожній сторінці | 226 КБ | 168 КБ (−26 %) |
| Словник перекладів у браузері | 27 КБ | 17 КБ |
| CSS сторінки житла (список) | 2 файли, +71 КБ карти | лише основний |

## Наслідки

- Новий розділ перекладів для клієнтського компонента додається в `CLIENT_NAMESPACES`, інакше падає тест.
- Важка бібліотека лише для одного режиму підключається через `next/dynamic` (як карта), а не статичним імпортом.
- Помилки в браузері звітуються через `reportError`, а не прямим імпортом `@sentry/nextjs`.
