# ADR 0007: ШІ-шар на DeepSeek

- Статус: прийнято (2026-11-04)

## Контекст
ТЗ передбачало Anthropic API з tool use: дешевша модель для розбору запитів і потужніша
для пояснень. Власник обрав DeepSeek: ключ уже є, API сумісне з форматом OpenAI,
підтримує function calling і JSON-відповідь (https://api-docs.deepseek.com/).

## Рішення
- **Свій інтерфейс `LLMClient`** (`tickets_api/llm/types.py`) і адаптер DeepSeek на httpx
  без SDK. Інший провайдер (Anthropic) — ще один адаптер, сервіси ШІ не змінюються.
- **Моделі в конфігу:** розбір — `deepseek-flash` (`LLM_MODEL_PARSER`), пояснення —
  `deepseek-v4-pro` (`LLM_MODEL_EXPLAINER`). Режим міркувань вимкнено
  (`thinking: disabled`): числа рахує код, модель лише витягує поля й формулює текст.
- **Промпти** — файли власника `rules/rules.md` + `sub-agents/<Роль>.md`, без змін. Поверх
  них код додає «технічний контракт» (точні типи полів JSON), бо в промптах його немає.
- **Код перевіряє все, що можна перевірити:**
  - розбір: IATA-коди лише з довідника (інструмент `lookup_airport`), критичні поля
    (звідки, куди, коли) перевіряє код — модель не перепитує про необов'язкове; якщо
    названо лише місяць, день обирає код за календарем цін;
  - пояснення: модель отримує готові числа (різниці, тривалості текстом, вік ціни) і
    рекомендацію скорингу. Кожне число в тексті має бути у вхідних даних, а
    `recommended_id` — збігатися зі скорингом. Порушення — одна спроба виправити з
    переліком проблем; знову порушення — пояснення не показуємо.
- **Розмовний агент** (`ai/assistant.py`, `POST /ai/chat`, модель `LLM_MODEL_ASSISTANT`).
  Замінив у UI поле «Опишіть поїздку»; `/ai/parse` лишився для eval.
  - **Пам'ять:** до закриття вкладки. Розмова лежить у `sessionStorage`, сервер її не
    зберігає. Браузер щоразу надсилає останні 20 реплік (лише ролі user/assistant) і
    поточний пошук з URL (`current_search`), тож «а прямі?» стосується того, що на екрані.
  - **Інструменти:** `lookup_airport`, `search_flights` (FlightSearchService + скоринг,
    параметри перевіряє код), `price_calendar` (кешований календар).
  - **Відповідь:** код перевіряє, що кожне число є в результатах інструментів, контексті
    чи розмові. Порушення — одна спроба виправити, потім `fallback` (UI пише свій текст).
  - **Знайдене:** UI відкриває `search` звичайною сторінкою результатів. Сторінка бере
    його з кешу провайдерів, тож квота не витрачається вдруге.
  - **Ліміти:** до 2 нових живих пошуків і `LLM_MAX_CALLS_PER_CHAT_TURN` викликів моделі
    на репліку.
  - **Промпт ролі** — `ai/prompts/Travel-Assistant.md` поверх `rules/rules.md`. У
    `sub-agents/` цієї ролі немає, а цю папку код не змінює.
- **Ліміти й облік:** не більше `LLM_MAX_CALLS_PER_SEARCH` викликів на запит
  (`MeteredLLM`); кожен виклик — у таблицю `llm_usage` (токени з урахуванням кешу
  промптів, вартість у $ за `llm/pricing.toml`, затримка). Відповіді кешуються в Redis
  (`LLM_CACHE_TTL_S`), ключ містить відбиток моделі й промпту.
- **Без ШІ все працює:** `LLM_PROVIDER=off` (за замовчуванням) — `/ai/*` відповідають 503,
  UI ховає ШІ-блоки; збій моделі — пошук формою як раніше. `LLM_PROVIDER=mock` —
  детерміновані відповіді для e2e і розробки без ключа.

## Якість
30 тестових запитів (`apps/api/tests/fixtures/llm_eval/parser_cases.json`): прості,
відносні дати, місяць, кілька аеропортів, бюджет в іншій валюті, діти, уточнення, не про
подорожі, prompt injection. pytest проганяє їх на записаних відповідях (без мережі);
`uv run python scripts/eval_parser.py [--record]` — наживо. Листопад 2026: 30/30,
≈ $0.009 за прогін. Набір невеликий і писався разом з парсером — нові формулювання
варто додавати туди ж.

## Наслідки
- **Вартість** (листопад 2026): розбір ≈ $0.0002–0.0003 (системний промпт кешується
  DeepSeek), пояснення ≈ $0.0017–0.0034 (друга спроба — лише при порушенні контракту).
- **Приватність:** текст запиту обробляє DeepSeek (сервери в КНР). Логи й `llm_usage`
  тексту не містять — лише розміри й вартість; UI попереджає не вводити особисті дані.
  Для GDPR це має бути в політиці приватності (етап 8).
- **Ціни моделей** змінюються — `llm/pricing.toml` треба оновлювати вручну. Години пік
  без урахування китайських свят: у ці дні вартість трохи завищена, а не занижена.
