# ADR 0061 — Швидкодія вебу: без зсувів макета

Статус: прийнято (V3, етап 9). Доповнює [ADR 0035](0035-frontend-performance.md).

## Вимірювання

`PERF=1 npx playwright test perf` (`e2e/perf.spec.ts`): продакшн-збірка, тестовий API з mock-джерелами; кожна сторінка — у
новому контексті (холодний кеш). LCP і CLS — `PerformanceObserver`, TBT — сума довгих задач понад 50 мс, затримка
взаємодії — Event Timing (друк у полі міста, відкриття ШІ-чату). Профілі: комп'ютер 1280×900 і «середній телефон»
390×844, CPU ×4, повільний 4G (150 мс, 1,6 Мбіт/с). Пороги «добре» Web Vitals (p75): LCP < 2,5 с, CLS < 0,1, INP < 200 мс.

## Знайдено

| Проблема | Було | Причина |
|---|---|---|
| Сторінки результатів (рейси, житло, поїздка, Explore) «підскакували» | CLS 0,15–0,26 (телефон), 0,08–0,18 (комп'ютер) | форма над результатами згорталась лише після гідратації; заглушка форми в статичній оболонці — повна форма |
| Телефон: видача підскакувала на ~600 px | CLS 0,15 | панель фільтрів до гідратації — повна, після — кнопка «Фільтри» |
| Підказка до нового — пізній LCP і зсув | LCP 2,6 с (Explore з картою, телефон) | підказка з'являлась лише після гідратації (localStorage) |
| Футер у полі зору, доки йдуть результати | CLS 0,08–0,1 (комп'ютер) | заглушка результатів коротша за екран |
| Тема й стан сторінки — після першого кадру | (спалах світлої теми) | `next/script` beforeInteractive у App Router виконує рантайм Next, а не браузер синхронно |

## Рішення

- **Ранній синхронний скрипт у `<head>`** (`layout.tsx`): тема, `data-search="results"` (є дата в адресі й не чернетка —
  `lib/search-shell.ts`), `data-hints` (закриті підказки — `lib/hints.ts`). Сталий текст без даних користувача —
  єдиний `dangerouslySetInnerHTML` у вебі (ADR 0057). Переходи без перезавантаження — `SearchShellSync`.
- **Заглушки обох станів** у статичній оболонці (`ShellChoice`): старт — справжня форма й заголовок (`HeroTitle`,
  синхронний), результати — `CollapsedSearchSkeleton` точної висоти (176 / 108 px); CSS за `data-search` показує одну.
  Заголовок і форма згортаються за одним правилом (`isDraft` + розбір пошуку).
- **`CollapsibleSearch` — нативний `<details>`**: згорнутий уже в HTML, без JS розгортається так само.
- **`FilterShell` до гідратації** рендерить і кнопку (телефон), і панель (≥ lg) — CSS показує потрібну; без JS —
  `<noscript>` показує панель, як і раніше.
- **Підказки** рендерить сервер, закриті ховає CSS до першого кадру.
- **Заглушки результатів** — не нижчі за екран (`min-h-dvh`).

## Обмеження

- TBT сторінок з картою на телефоні — 270–450 мс (розбір і запуск MapLibre); карта — головний вміст цього режиму,
  тож відкладати її нікуди. Списковий режим — без цього.
- Фото напрямків — мініатюри Вікімедіа 500 px: на великій картці Explore на комп'ютері вони м'якуваті. Більші розміри
  на льоту Вікімедіа обмежує (429) — їх треба брати заздалегідь у `scripts/update_destinations.py`.
- Лабораторні вимірювання (mock API, локальна мережа): поле (p75 реальних людей) на Vercel + Render free повільніше —
  особливо перший запит після сну Render.
