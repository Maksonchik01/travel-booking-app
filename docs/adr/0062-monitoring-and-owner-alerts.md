Статус: прийнято (V3, етап 10). Знахідка H4 аудиту ([v3-audit.md](../v3-audit.md)).

## Технічні сповіщення (`services/ops_watch.py`, воркер, раз на 15 хв)

API недоступний (двічі поспіль не 200 — один збій може бути пробудженням Render free); бюджет платного API ≥ частки
попередження; джерело — ≥ 50 % помилок за добу (від 10 запитів); сповільнення джерела — сьогодні > 2× середнього за
тиждень і > 5 с; витрати ШІ ≥ 80 % ліміту; сплеск відмов 429 (`OPS_RATE_LIMIT_SPIKE`). Кожна проблема — не частіше, ніж
раз на 6 год. Канали — Telegram (`OPS_TELEGRAM_CHAT_ID`, той самий бот) і/або email (`OPS_ALERT_EMAIL`); без них — лог.
Критичні винятки — правила сповіщень Sentry. Падіння всього Render (і воркера) помітить лише зовнішній монітор аптайму.

## Розділ `/ops` (веб)

- Доступ — лише логіни з `OPS_ADMINS` (env вебу) і лише з `INTERNAL_API_KEY`; решта — сторінка «не знайдено» (у
  стрімінгу зі статусом 200 — перевіряємо вміст, жодних даних зведення). Сторінка не індексується.
- Дані — `GET /ops/summary` з сервера Next із `X-Internal-Key`; ключ у браузер не потрапляє.
- **Ліміти без редеплою:** форма → server action → `PUT /ops/budgets` → перевизначення в Redis
  (`api:budget:overrides`), пріоритетні над `.env`; процеси API й воркера перечитують їх раз на 30 с; «повернути з
  .env» — прибрати перевизначення.
