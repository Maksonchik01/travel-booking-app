# ADR 0060 — Збої залежностей: зрозуміла відповідь замість «вас не впізнали»

Статус: прийнято (V3, етап 7).

## Сценарії відмови (стан після перевірки)

| Збій | Поведінка | Де |
|---|---|---|
| Тайм-аут, 429, 5xx, некоректна відповідь джерела | джерело позначене (`timeout` / `rate_limited` / `error`), решта працює; повтор лише 502–504 й обриву | `ProviderGate`, `FlightSearchService` (ADR 0034) |
| Часткова недоступність джерел, порожньо | показуємо отримане, `EmptySuggestions` з однією зміною | ADR 0040 |
| Вичерпано бюджет API / ШІ | `rate_limited` для джерела; ШІ — «недоступний», пошук працює | ADR 0055, 0056 |
| Redis недоступний | кеш, ліміти й бюджет пропускаються, пошук працює | ADR 0034, 0055 |
| Помилка ШІ-провайдера | `unavailable` / `fallback`, без вигаданих чисел | ADR 0007 |
| Перерваний пошук, повільне з'єднання | тайм-аут у браузері → `RetryNotice` з повтором; стан пошуку — в URL, введене не губиться | ADR 0029 |
| **База (Supabase) недоступна** | **виправлено:** див. нижче | |

## Знайдено й виправлено

- **API віддавав голий 500** для кабінету, входу, підписок і публічної поїздки, коли база недоступна. Тепер
  `core/errors.py`: збій з'єднання (`OperationalError`, `InterfaceError`, `OSError`, `TimeoutError`) → 503
  `{"detail": "unavailable"}` з `Retry-After: 30`. Порушення обмежень (`IntegrityError`) сюди не потрапляють. Пошук від
  бази не залежить: історія цін пишеться «з найкращих намірів».
- **Збій виглядав як вихід з акаунта.** `requireAccount` на будь-яку невдачу перенаправляв на вхід — під час збою
  бази чи «пробудження» API на Render людину відправляло логінитися знову (і вхід теж не працював). Тепер на вхід —
  лише при 401; інакше `account/error.tsx`: «Кабінет тимчасово недоступний… Ви не вийшли з акаунта» з повтором.
- **Публічна поїздка під час збою казала «посилання вимкнено».** `request()` розрізняє `not_found` (404); інший збій —
  «тимчасово не вдалося завантажити, посилання робоче» з повтором. Форма входу показує `authErrors.unavailable`.
