# ADR 0011: Акаунти, кабінет і діалоговий Telegram-бот

- Статус: прийнято (2026-11-07)

## Контекст
Потрібен особистий кабінет: вхід за логіном/паролем і через Google, профіль (ім'я, прізвище,
пошта), зміна пошти й пароля, історія пошуків і збережені пошуки, а також повноцінний бот
(не лише підтвердження підписки з сайту). Мінімум персональних даних (GDPR).

## Рішення
- **Паролі — scrypt зі stdlib** (`n=2**14, r=8, p=1`, сіль 16 байт, у потоці), формат
  `scrypt$n$r$p$salt$hash`. Мінімум 8 символів. Після 5 невдалих входів — пауза 15 хв (Redis).
- **Сесії в БД, не JWT**: випадковий токен у httpOnly-cookie `tickets_session` (SameSite=Lax),
  у БД — лише SHA-256. Next передає його в API як `Authorization: Bearer`. Вихід — видалення
  рядка; «вийти всюди» й зміна пароля скасовують решту сесій (поточна лишається).
- **Google — OAuth 2.0 Authorization Code + PKCE S256**, ендпоінти з discovery-документа;
  `state` — у Redis і в короткій cookie. Існуючий акаунт прив'язуємо лише за підтвердженою
  Google поштою (`email_verified`). Redirect URI: `<PUBLIC_WEB_URL>/api/auth/google/callback`.
- **Пошта необов'язкова**; нова адреса діє лише після переходу за посиланням з листа
  (одноразові токени `auth_tokens`, у БД — хеш). «Забули пароль» не розкриває, чи є адреса.
- **Історія пошуків** пишеться сервером після рендеру результатів (`after()`), повторний той самий пошук лише піднімається нагору,
  до 200 записів; **збережені** — до 100, з назвою. Зберігаємо лише рядок параметрів
  URL пошуку (перевірений шаблоном), не результати.
- **Бот:** команди `/new` (діалог: звідки → куди → дата → повернення → поріг, з кнопками
  вибору аеропорту), `/list` (кнопки «Вимкнути», «Поріг»), `/stop`, `/cancel`, `/link`,
  `/help`; меню команд — `setMyCommands` на старті воркера. Під сповіщенням — «Тиша 7 днів».
  Підписка з бота активна одразу (людина вже в чаті). Стан діалогу — Redis, 1 год.
  `callback_data` діє лише на підписки того ж чату. Повідомлення — HTML з екрануванням.
- **Прив'язка Telegram до акаунта:** кабінет видає одноразове посилання
  `t.me/<бот>?start=link_<код>` (30 хв); бот записує chat id в акаунт і переносить
  підписки цього чату в кабінет.

## Наслідки
- Без SMTP листи (підтвердження пошти, відновлення пароля) лише в лог: локально скидання
  пароля без пошти неможливе.
- Немає 2FA й підтвердження входу з нового пристрою — до етапу 8.
- Лімітів на кількість реєстрацій з однієї IP немає — до етапу 8.
