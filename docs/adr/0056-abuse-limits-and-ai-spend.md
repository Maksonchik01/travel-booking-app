# ADR 0056 — Ліміти зловживань і витрати ШІ

Статус: прийнято (V3, етап 3). Знахідки C3, H1–H3 аудиту ([v3-audit.md](../v3-audit.md)).

## Рішення

- **Кошики за вартістю операції** (`core/rate_limit.py`, вікно — година):

  | Кошик | Операції | За замовчуванням |
  |---|---|---|
  | `search` | пошук перельотів, житла, Explore; місце біля житла | 40 |
  | `heavy` | поїздка, «Знайти дешевший варіант», «Оновити ціни» | 15 |
  | `check` | перевірка продавців рейсу, тарифи продавців житла | 60 |
  | `lookup` | календар, матриця, історія цін, місця, країни, сторінка об'єкта з кешу | 600 |
  | `ai`, `auth`, `clicks`, `events` | як раніше | 90 / 20 / 200 / 600 |

- **Акаунт.** Веб передає сесію (`Authorization: Bearer` з httpOnly-cookie, `clientIdentityHeaders`) у запитах до
  API. Для `search`, `heavy`, `check`, `lookup`, `ai` перевірений токен дає власний кошик акаунта з лімітом ×
  `RATE_LIMIT_ACCOUNT_MULTIPLIER` (2): кілька людей за одним IP (офіс, мобільний оператор) не блокують одне
  одного. Перевірка — `user_for_session`, результат кешується в Redis на 5 хв (ключ — хеш токена). Невідомий чи
  підроблений токен — кошик IP: новим токеном ліміт не обійти. БД недоступна — кошик IP.
- **Одночасні пошуки** (`concurrent_searches`): не більше `MAX_CONCURRENT_SEARCHES` (3) живих пошуків одного
  клієнта разом (`search`, `heavy`, чат помічника) — ліміт за годину рахує лише старти, а пошук триває до 30–90 с.
  Лічильник у Redis зменшується в `finally`; запас — TTL 3 хв, якщо процес упав.
  Без `INTERNAL_API_KEY` API не розрізняє відвідувачів (усі — IP Vercel), тож для анонімних цей ліміт не діє.
- **Розмір тіла** (`core/body_limit.py`): понад 1 МБ — 413 (за `Content-Length` і потоком байтів). Решта меж
  параметрів — у моделях Pydantic: дати (≤ року, період ≤ 3 міс), до 3 аеропортів, до 9 пасажирів, довжина
  повідомлень помічника (500 символів, 20 реплік).
- **Витрати ШІ** (`LLMSpendGuard` у `llm/metered.py`): добовий і місячний ліміт у USD (`LLM_BUDGET_DAILY_USD` = 2,
  `LLM_BUDGET_MONTHLY_USD` = 20) для всіх процесів — Redis у мікродоларах. Перед кожним викликом моделі —
  перевірка; після — фактична вартість. Досягнуто — `LLMBudgetExceededError`: ШІ відповідає «недоступний», пошук
  без ШІ працює. Ліміти викликів на один запит (`LLM_MAX_CALLS_*`) і облік у `llm_usage` — як раніше.
- **ШІ: інструменти й ін'єкції** — без змін, перевірено: модель викликає лише задані інструменти режиму, параметри
  валідує код (IATA з довідника, дати, фільтри), ціни й рейси — лише з пошуку SkyPack, числа у відповіді
  звіряються з результатами інструментів; дані провайдерів — недовірені (ADR 0007, 0022).

## Наслідки

- Один виклик моделі може трохи перевищити ліміт витрат — наступний уже ні.
- Без Redis ліміти не діють (як і раніше) — захисна сітка; бюджет платних API теж (ADR 0055).
- Сторінка конфіденційності описує лічильники (IP чи акаунт, до години, без вмісту запитів).
