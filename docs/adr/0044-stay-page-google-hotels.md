# ADR 0044 — Сторінка об'єкта житла й Google Hotels через scrape.do

Статус: прийнято.

## Контекст

Власник попросив:
- фото для кожного готелю;
- окрему сторінку об'єкта з описом, усіма фото, номерами й цінами;
- на картці пошуку — кнопку переходу на сайт із цим готелем.

У mock-джерела житла (ADR 0008) немає фото, опису й посилань. Власник обрав реальне джерело — Google Hotels через scrape.do
(той самий токен, що й для перельотів, [ADR 0043](0043-scrapedo-google-flights.md);
[документація](https://scrape.do/documentation/google-scraper-api/hotels/)).

Перевірено реальними запитами (листопад 2026, `apps/api/tests/fixtures/scrapedo/hotels_*.json`, `hotel_detail_*.json`).

| Що | Як у джерела |
|---|---|
| Пошук `GET /plugin/google/hotels` (`q` = "<місто> hotels", дати, валюта) | до 20 об'єктів; 7–9 фото (`lh3.googleusercontent.com`, мініатюри 287×192, великий розмір — параметр після «=»); опис (не завжди); клас; рейтинг 0–5 і кількість відгуків; координати; час заселення й виїзду; ціна за ніч і за весь період; `detail_token` |
| Продавці `GET /plugin/google/hotels/detail` (`detail_token`) | `booking_sources[]`: назва, ціна за ніч і за весь період, `click` (відносне посилання google.com: `/travel/lodging/clk?…` чи рекламне `/aclk?…` з `sponsored`) |
| Склад гостей | параметрів немає — ціни завжди на двох дорослих в одному номері |
| Типи номерів, харчування, скасування | немає |
| Податки в ціні | не сказано |
| Коди зручностей | не документовані |
| Тексти відгуків | немає |
| Посилання на сторінку готелю | немає. Сторінка сутності Google Hotels без браузера веде на consent і `unsupported`, тож використовуємо пошук `travel/search?q=<назва> <місто>` (перевірено: відкриває цей готель) |
| Ціна | 10 кредитів за запит, спільні з перельотами (1000 на місяць) |

## Рішення

### API

- **Адаптер** `providers/scrapedo_stays.py`, `ScrapeDoStayProvider` (`STAY_PROVIDERS=scrapedo`).
  - Запит до scrape.do — лише з бекенду, спільний `scrapedo_get` (токен у query string, у помилках — лише статус).
  - **Що беремо з відповіді:**
    - `Stay.images` — великі фото (`=w1280-h853-k-no`, до 12, лише з хоста фото Google);
    - `image_url` — мініатюра для картки;
    - `description` (недовірений текст, лише показуємо);
    - `check_in_time` / `check_out_time`;
    - рейтинг ×2 (шкала 0–10);
    - відстань до центру — від центру міста з довідника.
  - **Чого джерело не дає — не вигадуємо:** скасування, сніданок і зручності лишаються невідомими (`None` чи `[]`).
  - **`Stay.taxes_included = None`:**
    - на картці й сторінці об'єкта пишемо «чи є податки — уточнює продавець»;
    - у сумі поїздки таке житло позначене як «орієнтовне», а не «підтверджене» (`trip_costs`).
  - **Склад гостей:** 1–2 дорослих без дітей в одному номері. Інший склад — `ProviderUnsupportedError("guests")` → статус `unsupported` з поясненням, ціну не вигадуємо. Для одного дорослого ціна — номера на двох.
  - **Тарифи** (`POST /stays/rates`) — продавці з `booking_sources` як `StayRate`:
    - `room_name=""` (номер не названо — UI пише «номер на двох, тип обираєте в продавця»);
    - `taxes_included=None`;
    - `is_property` — продавець з назвою готелю (сайт самого готелю);
    - `sponsored` → позначка «Реклама»;
    - посилання — лише на `google.com/travel/lodging/clk?` і `google.com/aclk?`.
- **Кеш.**
  - `CachedStayProvider` — та сама механіка Redis, що й у перельотів (`RedisCache` у `providers/cached.py`): TTL, один виклик на однакові запити, замок між процесами.
  - Фільтри, профіль і уподобання в ключ не входять: їх застосовує сервіс.
  - Тарифи беруть `detail_token` з кешу пошуку (`ScrapeDoStayProvider.lookup` = кешований `search`), а не новим пошуком.
- **`POST /stays/detail`** (`StayDetailRequest` → `StayDetailResult`): об'єкт з видачі тих самих дат і гостей.
  - Платне джерело відповідає з кешу пошуку.
  - Зниклий об'єкт — `not_found`.
- **Алерти** житла й поїздки платне джерело не використовують (`alerts_factory`): регулярні перевірки з'їли б кредити. Як і SerpApi в алертах перельотів.

### Веб

- **Сторінка об'єкта** `/stays/hotel?<параметри пошуку житла>&src=&id=` (`stayHotelHref`, `parseStayRef`):
  - заголовок (тип, клас, рейтинг, відстань, час заселення й виїзду);
  - галерея (`stay-gallery.tsx`: велике фото й мініатюри, «Ще N»; перегляд на весь екран у `<dialog>` зі стрілками, клавіатурою й стрічкою мініатюр);
  - «Про об'єкт»;
  - «Номери й ціни» — `StayHotelRates` підвантажує тарифи сам (1 запит, далі кеш 30 хв);
  - «Деталі й умови» (`StayDetails`);
  - бічна панель: ціна, свіжість, «Відкрити в Google Hotels», «В обране», «Додати до поїздки»;
  - «До результатів пошуку» — той самий пошук.
- **Картка житла:**
  - назва й фото ведуть на сторінку об'єкта;
  - фото видно й на телефоні (смуга зверху) з лічильником фото;
  - кнопки «Фото й деталі» та «Відкрити в Google Hotels» (`/out`, нові префікси в `outbound.ts`).
- **Фото** браузер вантажить напряму з `lh3.googleusercontent.com` без Referer — як фото на картці житла й раніше. Через оптимізатор Next не пропускаємо: 9 фото на об'єкт швидко вичерпали б ліміт перетворень Vercel. Це описано в «Конфіденційності».

## Наслідки

- **Кредити scrape.do:**
  - пошук житла — 10;
  - відкриття сторінки об'єкта — 10 (тарифи);
  - планувальник поїздки — до 3 пошуків житла (вікна дат);
  - повтор протягом `PROVIDER_CACHE_TTL_S` (30 хв) — безкоштовно.
  - Разом із перельотами (ADR 0043) 1000 безкоштовних кредитів вистачить ненадовго — стежте за залишком (заголовок `scrape.do-remaining-credits`).
- **Фільтри** скасування, сніданку, зручностей і передоплати для Google Hotels порожні (`facets.available`): даних немає.
- **«Резюме відгуків»** для Google Hotels не формується (текстів немає).
- **Mock лишається** для розробки, e2e і без ключа. Сторінка об'єкта працює й з ним — без фото, чесно «Фото джерело не дає».
