# ADR 0036 — Мови текстів, які формує сервер

Статус: прийнято (модуль 18a, 18.1).

## Контекст

Веб уже був повністю на перекладах (`messages/{en,uk,ru}.json`, ADR 0024). Сканування коду знайшло лише продубльовані самоназви мов. Але частину текстів формує API, і вони були тільки українською:
- сповіщення про ціну (Telegram і листи), лист підтвердження підписки;
- усі ~70 реплік Telegram-бота й меню його команд;
- листи акаунта (підтвердження адреси, відновлення пароля);
- дані для ШІ: «3 год 10 хв», «5 год тому», «Найдешевший», «Економ». Модель цитує ці значення, тож англійська відповідь виходила змішаною. Мітки карток у чаті («Найдешевший», «Поточна поїздка») показувалися в UI українською за будь-якої мови;
- тексти помилок підписки (422 `detail`). UI їх не показував, лише «не вдалося».

## Рішення

- **Пакет `tickets_api/i18n`:**
  - каталоги `messages/{en,uk,ru}.json`, `t(key, **params)` з `{name}`-підстановками;
  - множина (`count`) за правилами CLDR: uk/ru — one/few/many, en — one/other;
  - `Labels` — колишні словники назв, але мовою контексту на момент звернення.
- **Мова — у контекстній змінній** (`use_locale`), один раз у точці входу:
  - **сповіщення** — мовою підписки (`alerts.locale`, міграція 0021; наявним рядкам — мова акаунта власника);
  - **бот** — мовою прив'язаного акаунта, інакше мовою Telegram (`language_code`: наші мови як є, будь-яка інша — англійська). Меню команд задане для кожної мови, за замовчуванням англійське. Підписки з бота отримують цю мову;
  - **листи акаунта** — `users.locale`. Реєстрація тепер зберігає мову інтерфейсу;
  - **ШІ** — `explain`, `analyze`, `reply` обгортають побудову даних мовою відповіді.
- Без жодних відомостей про мову — українська: так поводився сервер до модуля 18, і так лишаються старі підписки без мови.
- **Помилки підписки мають код** (`AlertError.code`: `past_date`, `too_far`, `owner_limit`…). API віддає його в `detail`, веб показує текст своєю мовою (`alerts.errors.*`).
- Самоназви мов — одне джерело, `LOCALE_NAMES` в `i18n/config.ts`.

## Перевірки

- `test_i18n.py`: однакові ключі й плейсхолдери в трьох каталогах, повні форми множини, тексти сповіщень і даних ШІ кожною мовою.
- Інтеграційні тести: бот англійською за мовою Telegram і мовою акаунта, якщо він прив'язаний; лист підписки мовою підписки; меню команд для кожної мови.
- `hardcoded-text.test.ts`: у вебі немає кириличних рядків поза коментарями (виняток — самоназви мов).

## Наслідки

- Новий текст, який API надсилає людині, додається в усі три каталоги API, а не рядком у коді.
- Нова точка входу, що формує тексти без відомої мови, ставить `use_locale(...)`.
