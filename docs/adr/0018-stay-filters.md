# ADR 0018: Розширені фільтри житла — лише там, де є дані

- Статус: прийнято (2026-11-08); доповнює ADR 0008

## Контекст
ТЗ модуля 5: ціна (мін/макс за ніч і разом), тип (зокрема «інше»), гості (діти з віком,
кімнати, ліжка), рейтинг 7/8/9 з нормалізацією шкал, умови (безкоштовне скасування, сніданок,
без передоплати, оплата на місці), зручності, розташування (до центру, район, біля точки).
«Показувати тільки ті фільтри, для яких доступні достовірні дані». Реального джерела житла
поки немає (лише mock, ADR 0008).

## Рішення
- `Stay`: `kind` + `other`; `breakfast_included`, `prepayment` (none/required), `pay_at_property`,
  `beds`, `rooms`; зручність `balcony`. Невідоме — `None`, не «ні».
- `Guests`: `children_ages` (0–17, для кожної дитини або порожньо), `rooms` (1–5, не більше гостей).
- `StayFilters` (після провайдерів, як і раніше): ціни, умови, зручності (усі обрані), ліжка,
  відстань, райони, `near` + `radius_km` або `near_airport` (координати бере сервіс із довідника —
  геокодування адрес немає). Явно обрана умова вимагає ПІДТВЕРДЖЕНОГО значення: невідоме не
  проходить (людина обрала «сніданок включено», а не «можливо»).
- `normalize_rating(значення, шкала)` — для адаптерів джерел зі шкалою 5/100 тощо.
- `StayFacets.available` — які поля відомі хоча б для одного об'єкта; `amenities`/`districts` з
  кількістю. UI показує фільтр лише за наявних даних (у т. ч. «біля аеропорту» — якщо є
  координати й аеропорти міста).

## Наслідки
- Нове джерело житла автоматично «вмикає» лише ті фільтри, які воно реально наповнює.
