# ADR 0012: Продакшн-база — Supabase Postgres

- Статус: прийнято (2026-11-07)

## Контекст
Безкоштовний Postgres на Render видаляється через 30 днів. Потрібна безкоштовна керована
база в Європі без зміни коду доступу до даних (SQLAlchemy async + Alembic).

## Рішення
- **Від Supabase — лише Postgres.** Вхід, сесії, міграції й доступ до даних лишаються нашими
  (ADR 0011); Supabase Auth, Storage і Data API не використовуємо.
- **Підключення — Session pooler** (`postgres.<ref>@aws-…pooler.supabase.com:5432`, IPv4):
  пряме підключення на безкоштовному плані лише IPv6, а Transaction pooler (6543) — для
  serverless і без prepared statements, які використовує asyncpg. Регіон — Frankfurt, як Render.
- **RLS на всіх таблицях без політик** (міграція 0009): Supabase відкриває схему `public`
  через Data API публічним ключем; RLS без політик закриває її для anon/authenticated, а бекенд
  працює від власника таблиць і RLS обходить. Тест `test_row_level_security` вимагає RLS для
  кожної таблиці моделей — нова таблиця вмикає його у своїй міграції. Data API вимкнено в
  налаштуваннях проєкту (додатковий захист).
- `DATABASE_URL` з libpq-параметрами (`postgresql://…?sslmode=require`) нормалізується в
  `postgresql+asyncpg://…?ssl=require` (`Settings._async_driver`).
- Локальна розробка й тести — Postgres у Docker, як і раніше; продакшн-дані тести не чіпають.

## Наслідки
- Безкоштовний план: 500 МБ, проєкт ставиться на паузу після 7 днів без активності (воркер
  звертається до бази щохвилини, тож на практиці — ні).
- Міграції запускає API на старті (CMD образу), як і з базою Render.
