# ADR 0041 — Пошук перельотів з кількох джерел

Статус: прийнято (модуль 22).

## Контекст

- **Чому видача була лише з Google Flights:**
  - пошук (`FLIGHT_PROVIDERS`) мав лише `serpapi`, а Travelpayouts був тільки в календарі;
  - якби Travelpayouts додали в пошук, `_explore` вимкнув би розвідку гнучких дат: розвідником вважалося лише джерело календаря, якого немає серед пошукових.
- **Що вже було й працювало:**
  - агрегація кількох джерел з graceful degradation;
  - групування однакового рейсу (`offer_groups`), рядки продавців у картці;
  - продавці рейсу наживо: `POST /flights/sellers`, `booking_options` Google Flights — авіакомпанія напряму й агенції.

### Доступні джерела (перевірено в листопаді 2026)

| Джерело | Доступ | Рішення |
|---|---|---|
| Google Flights (SerpApi) | є, квота 250 запитів на місяць | живий пошук; продавці рейсу — на вимогу |
| Google Flights (scrape.do) | є, 1000 кредитів на місяць (10 за запит) | живий пошук, туди-назад — два квитки в один бік ([ADR 0043](0043-scrapedo-google-flights.md)) |
| Aviasales Data API (Travelpayouts) | є, безкоштовно, кеш 2–7 днів | кешовані ціни продавців (`gate`: Kiwi.com, Clickavia…) у пошуку й календарі |
| Aviasales Flight Search API (живий) | лише від 50 000 MAU, за заявкою | недоступно |
| Skyscanner Travel API | лише схвалені партнери з великою аудиторією | недоступно |
| Kiwi.com Tequila | нові партнери — лише за запрошенням (з 2024) | недоступно |
| Trip.com, Expedia, Booking.com Flights | публічного API цін перельотів немає (партнерські посилання) | недоступно |
| Ryanair, Wizz Air, easyJet | офіційного API цін немає; скрапінг заборонений правилами | не робимо |
| Lufthansa, AF-KLM, LOT, Turkish | API для партнерів/агентів (NDC), не для редиректу | недоступно |
| Duffel та інші NDC-агрегатори | продаж через себе (ми не продаємо квитків) | не підходить |

Ціни авіакомпаній напряму й агенцій ми бачимо там, де їх показує Google Flights (`is_airline` у продавцях).

## Рішення

- **Джерела.** У пошуку обидва джерела: `FLIGHT_PROVIDERS=serpapi,travelpayouts`. Квоти SerpApi Travelpayouts не витрачає.
- **Етапи.**
  - *Атрибут `live`.* `FlightProvider.live = False` позначає кешоване джерело (Travelpayouts); перевіряє `is_live`.
  - *Гнучкі дати.* Кешовані джерела календаря — розвідники, навіть якщо вони й пошукові. Їхня відповідь уже є пропозиціями пошуку, тож удруге їх не питаємо. Живе джерело перевіряє лише найдешевші пари дат.
  - *Продавці.* Етап 2 — продавці рейсу (`booking_options` Google Flights: авіакомпанія напряму й агенції):
    - для першої картки видачі перевіряються самі, після показу сторінки (`SellerOffers autoCheck`, `AUTO_SELLER_CHECKS = 1` у `app/[locale]/page.tsx`);
    - для інших — кнопкою.
    - Кожна перевірка — 1 запит SerpApi (кеш 30 хв) і запит з ліміту `search`. Пошук коштує на 1 запит квоти більше.
    - Не вдалося — лишається кнопка, без помилки.
- **Однаковий рейс.** Ключ — номери ВСІХ рейсів маршруту (`normalize_flight_number`: «LO 0437» = «LO437»), місцевий час вильоту й пересадки в кожному напрямку.
  - Пересадку без сегментів (Travelpayouts дає лише перший номер) не ототожнюємо.
  - Контрольний пошук показав, що за першим номером LX1349 з різними другими рейсами за 111 € і 189 € було б «одним рейсом».
- **Порядок «від найдешевшого»** — `comparable_order`:
  - вартість за всіх пасажирів і весь маршрут у валюті пошуку (копії за курсом ЄЦБ);
  - з потрібним багажем, якщо його ціна відома.
  - **У кінці:** ціна без курсу, ціна `needs_recheck` (стара кешована — у продавця вже інша) і невідомий потрібний багаж.
  - Картка рейсу — перший у групі за тим самим порядком.
  - Веб додає сортування «Виліт» (місцевий час).
- **Гнучкі дати.** Якщо живе джерело перевірило пару дат, показана ціна — його (`verified`). Кешована ціна на ті самі дати — старіший доказ.
- **Охоплення (діагностика).**
  - `FlightSearchResult.coverage` (`SearchCoverage`):
    - джерела — статус, живе чи кешоване, отримано й показано;
    - продавці;
    - рейси й рейси з кількома продавцями;
    - живі ціни.
  - Лог `flight_search.coverage` — лише лічильники й назви джерел.
  - Лічильники за добу в Redis (`ops:coverage:*`, 8 днів) → `coverage` у `/ops/summary`.
  - UI лише чесно пише: «Найнижча ціна — серед джерел, перевірених у цьому пошуку: …».

## Наслідки

- Travelpayouts на точні дати часто не має даних (кеш пошуків Aviasales). Найбільше він дає в гнучких датах і календарі.
- Нове джерело додається гілкою в `providers/registry.py`. Кешоване оголошує `live = False`.
- Нове кешоване джерело можна додати без змін у скорингу, API чи UI. Нове живе витрачає свою квоту на кожен пошук.
- Новий спосіб доступу до Skyscanner, Kiwi чи живого Aviasales — після схвалення партнерства: це рішення власника, не код.
