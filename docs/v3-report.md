# SkyPack V3 — фінальний звіт

Дата: 2026-11-11. Етапи 1–11 ТЗ V3; початковий аудит і знахідки — [v3-audit.md](v3-audit.md).

## Оцінка готовності

**Limited Testing Only** — до виконання трьох дій власника (розділ «Що зробити вам»); після них — **Ready for Beta**.

Блокувальних проблем у коді не лишилось: критичні знахідки виправлено, усі автоматичні перевірки зелені. Обмеження —
у продакшн-конфігурації, яку я не міг перевірити без доступу до дашбордів: чи заданий `INTERNAL_API_KEY` у Vercel і
Render (без нього ліміти спільні на весь сайт), чи налаштовані канали сповіщень і чи є хоч одна резервна копія бази
(Supabase Free їх не робить).

## 2. Виправлені проблеми (знайдені під час робіт)

- **Відкрите перенаправлення після входу** (`next=/\evil.example`) — `safeLocalPath`.
- **Подвійний платний запит**, коли очікування чужого замка кешу (25 с) коротше за живий пошук (30 с).
- **Неправдоподібні пропозиції джерел** (приліт до вильоту, повернення до прибуття, податки > ціни, дата не з запиту,
  житло не на ті ночі) потрапляли у видачу й історію цін.
- **Збій бази виглядав як вихід з акаунта**: кабінет відправляв на вхід; API віддавав голий 500; публічна поїздка
  казала «посилання вимкнено».
- **Зсуви макета** на сторінках результатів (CLS до 0,26), пізній LCP через підказку, скрипт теми — після першого кадру
  (спалах світлої теми).
- **Контраст кнопок при наведенні** нижче WCAG AA (3,8:1) — тепер темніше, 6,3:1.
- **Облік кешу** рахував приєднання до однакового запиту як «промах»; **лог** засмічувався при вичерпаному бюджеті.
- **Нестабільні тести**: перевірка алертів у випадковому порядку (≈ 1/12), три e2e — дії до гідратації.

## 5. Виявлені й невирішені вразливості / ризики

| Ризик | Рівень | Чому лишається |
|---|---|---|
| Без `INTERNAL_API_KEY` у продакшні ліміти й бюджети на клієнта спільні для всіх (усі — IP Vercel) | середній | не перевірено: потрібен доступ до дашбордів |
| Без Redis бюджети й ліміти не діють (fail-open) | низький | свідомо: інакше збій Redis зупиняв би пошук |
| Немає резервних копій бази (Supabase Free) | середній | дамп містить персональні дані — запускати й де зберігати вирішуєте ви |
| CSP без `script-src` (лише `frame-ancestors`, `base-uri`, `object-src`) | низький | nonce вимкнув би пререндер; XSS закриває React + сталий єдиний inline-скрипт |
| `https://www.google.com/aclk?` у дозволених переходах — відкрите перенаправлення Google | низький | офіційні рекламні посилання продавців з видачі |
| Місячний лічильник бюджету — календарний, квоти джерел — від дати підписки | низький | ліміти SkyPack нижчі за квоти із запасом |

## 7. Бюджетні ліміти й облік витрат

- **Принцип:** кожен HTTP-запит до джерела — через `ProviderGate` → `ApiMeter`: атомарний резерв у Redis до запиту
  (Lua — одночасні запити не проскочать ліміт), неуспішний запит повертає резерв (джерела списують лише успішні).
  Необов'язкові дорогі операції (автоперевірка продавців, «знайти дешевше», житло в Explore, тарифи житла) зупиняються
  на 80 % ліміту. Вичерпано — джерело `rate_limited`, решта працює.
- **Ліміти за замовчуванням:** SerpApi 40/год, 25/добу, 240/міс; scrape.do 200/год, 150/добу, 950/міс кредитів;
  ШІ $2/добу, $20/міс. Змінюються в `/ops` без редеплою або змінними в Render.
- **Вартість:** одиниці × ціна одиниці з конфігу (SerpApi $0,025 — Starter; scrape.do $0,000116/кредит — Hobby); на
  Free — фактично $0. **Собівартість успішного пошуку** = оцінка платних запитів за 7 днів / пошуки, що щось знайшли.

## 8. Продуктивність

LCP (комп'ютер / середній телефон): головна 0,07 / 1,0 с; рейси 0,7 / 1,0 с; житло 0,7 / 2,1 с; поїздка 0,4 / 1,6 с;
Explore 0,07 / 1,0 с; з картою 0,6–0,7 / 1,0–1,6 с; «Ваша поїздка» і кабінет на телефоні 0,4–0,6 с. CLS — 0 скрізь.
Затримка взаємодії — 16–40 мс. Обмеження: TBT режиму «Карта» на телефоні 270–460 мс (MapLibre). Навантаження:
400 запитів / 40 одночасно — p95 1,4–1,6 с (майже весь час — затримка джерел), 0 % помилок, 24 звернення до джерел.
Лабораторні цифри; на Render free перший запит після сну — до хвилини.

## 9. Що зробити вам

1. **`INTERNAL_API_KEY`** — однаковий у Vercel і Render (API) — перевірте; без нього ліміти спільні на весь сайт.
2. **Сповіщення:** Vercel — `OPS_ADMINS` (ваш логін SkyPack); Render, воркер — `OPS_API_URL`, `OPS_TELEGRAM_CHAT_ID`
   (і/або `OPS_ALERT_EMAIL`); Sentry — правило «A new issue is created»; зовнішній монітор аптайму на `/health/ready`.
3. **Перша резервна копія:** `scripts/backup_db.sh` (лише читання бази) → зберегти зашифровано; далі щотижня й перед
   ризиковими міграціями. Або тариф Supabase Pro (щоденні копії, 7 днів).
4. Необов'язково: ліміти бюджетів під свій тариф — у `/ops`.
